## 任务书 vs 实际落地

原任务书是 **4×5** 电网数独。迭代后产品与代码均为 **3×3 九宫格**。公告文案已按 3×3 写好。

| 维度     | 任务书 (4×5)                            | 实际 (3×3)                                                          |
| -------- | --------------------------------------- | ------------------------------------------------------------------- |
| Y 轴     | 1~4 取货口                              | **1~3 路**（`branchCount=0` 映射 row0；`>3` 不入盘）                |
| X 轴     | ≤20 / 20–100 / 100–300 / 300–800 / >800 | **≤100 / 100–500 / >500**                                           |
| 废解     | (Y=4, X=5)                              | **(row=2, col=2) = 3 路 × 千瓦**                                    |
| 搜索窗   | `maxWaste=1000`（或 1200）              | 求解器内部 `SEARCH_MAX_WASTE = 1200`                                |
| 电池底线 | 5%                                      | `MIN_BATTERY_CUTOFF = 5`                                            |
| 内部枚举 | 1~4 路                                  | 仍 `PARAM_LIMITS.MAX_BRANCHES = 4`                                  |
| 移动端   | Bottom Sheet                            | **居中 `DecisionMatrixModal`**（未引用的 `BottomSheet.tsx` 已删除） |
| 侧栏     | 去掉三大约束                            | `ConstraintsField.tsx` 已删；高级区只留相位差                       |

分享码仍锁历史槽位：`maxWaste=1000`、`minBatteryPercent=5`、`maxBranches=4`。求解器**忽略**这些 UI/分享值，改用内部宽窗。

## 已知坑（下一任不要踩）

1. **`SEARCH_MAX_WASTE`（1200）≠ 分享锁值 `maxWaste`（1000）**。改窗只动 `src/types/matrix.ts`；不要为了“对齐任务书 1000”去改分享 bit 语义。
2. **`solve()` 返回类型已是 `SudokuDecisionMatrix`，不再是 `SolutionResult[]`。** Worker 已拆字段；旁路直接 `new FactoryDesigner().solve()` 的脚本必须读 `.solutions` / `.matrix`。
3. 双轨是串行两次 `runOscillationPipelines()`，不是 Web Worker 并行。7665W 约数百 ms ～ 1s 量级；不要再叠一层无剪枝的 4 路全枚举。
4. 格子身份用 **对象引用**（`cell === preferred`、`findIndex(s => s === sol)`）。Worker 结构化克隆后，矩阵格与 `solutions[]` 必须是同一批对象图；不要对 matrix 再 deep clone 一次。
5. 蓝图导出仍打印 `params.maxWaste` 等。分享锁 1000/5/4，**不是**格子真实浪费。仪表盘以 `solution.waste` / `solution.minBatteryPercent` 为准。
6. README「参数与计算说明」仍写玩家手调 `minBatteryPercent` / `maxWaste`，且结构示例还是 `App.jsx`。发版前应改（本次交接文档不自动改 README，以免和上游文案冲突）。
7. `html.light` / Chart 画布：切主题必须走 `useTheme` 总线；只改 CSS class 不够，Chart.js 要强制 `update`。

## 侧栏最终板块（产品）

1. 目标发电量 `TargetPowerField`
2. 燃料配置 `FuelConfigField`
3. 基础常驻供电 `BasePowerBuilder`（含自动常驻开关；**求解仍双轨，开关不影响盘面超集**）
4. 其他设置 `OtherSettingsField`（地区 + 准入口限速）
5. 高级时序（折叠，相位差；不进 URL 的折叠状态）

`autoPlanBasePools` 仍编码进分享码。UI 关掉自动常驻时，求解器**仍然**跑 Track A+B；盘面会同时出现常驻补齐格与纯震荡格。若产品要“关掉就只出 Track B”，需要再改 `solve()`。
