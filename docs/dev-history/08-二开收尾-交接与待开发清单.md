## 四、待开发清单

### 7a. 常驻 + 自定义震荡池的「预算去重 + 联合校验」（原 #7）

- **目标**：同一种电池同时出现在「自定义常驻热能池」和「自定义震荡热能池」时，合计投料量若超过用户可用产能，给出**黄色提示**（不阻断求解）。
- **现状**：两边各自独立计算，没有合计校验。
- **线索**：常驻在 `FactoryDesigner.calculateBasePower`（`manualBaseLines`），池在构造器里的 `oscPools` 循环；可在侧栏 `BasePowerBuilder` 或新组件里做纯 UI 层提示。
- **验收**：常驻 2×高谷 + 池 0.9/分高谷时，如果用户声明产能不足，侧栏出现提示；不填产能时默认不提示。

### 7b. 「基础 + 自定义」场景下每日节省量丢失【bug】

- **现象**：7980W 需求、自定义池 = 2 条高容谷地满带 + 0.9/分中容武陵时，「燃料消耗」表里的**每天节省**整列消失/为空。
- **可能原因**：`FuelConsumptionTable` 把池投料量并进了总量，但节省列仍取 BOM 的 `savedRatePerDay`；这套场景下 BOM 的 saved 为 0，导致整列为空。
- **要求**：池消耗不参与节省计算，但原有 BOM 的节省值不能被吞掉；若该燃料只有池贡献，节省列显示 `-`。
- **涉及**：`src/components/solution/SolutionList/FuelConsumptionTable.tsx`（我上一版加的 `poolPerMin` 合并逻辑）。

### 7c. 该场景下「周期图表」全直线【bug】

- **现象**：0 路震荡（纯常驻 + 自定义池）时，周期图表当前发电量、电池、池功率全是直线；池有 0.9/分余量却没有波形。
- **可能原因**：纯 base 方案的 `powerLog` 只有 1~2 个采样点（代码里会把单点复制成两点），池波形按 `i × secondsPerPoint` 求值时点数不足，画不出周期。
- **要求**：池有震荡余量时，即使系统无震荡分支，也要按池的周期（`2D` 秒）展开足够长的横轴。

### 7d. 自定义震荡热能池的「满带示意图」对齐问题【UI】

- **现象**：1 台满带的 I+T 示意图里「燃料输入」被挤成两行，「发电」格子与输入格不在同一水平线；多口时更明显。
- **涉及**：`src/components/solution/SolutionDiagram/PoolBandDiagram.tsx`（3 行 CSS grid、固定 `2.6rem` 列宽）。
- **要求**：同一行元素垂直居中对齐、文案不换行（可缩字号或加宽列）。
