## 一、需求

周期图表（`ChartSection` → `SolutionChart`）标题栏新增一个**两档拨档开关**，默认在左档：

| 档位 | 名称 | 横轴窗口 | 说明 |
| --- | --- | --- | --- |
| 左（默认） | **周期显示** | `[-0.5P, 1.5P]`，共 2 个周期 | 按 **0.5 + 1 + 0.5** 排布：前半个周期 + 完整周期 + 后半个周期，让周期首尾衔接处（电池回升 / 断烧）落在图中间可见，而不是像现在贴着左右边缘 |
| 右 | **时间显示** | 10min / 30min / 2h / 12h / 1day / 7days | 档位对齐游戏本体「电能报告」的时间刻度，便于与游戏内曲线直接对照 |

现状：横轴固定 `[0, P]`（`P = solution.period`，经 `TARGET_SECONDS_PER_POINT = 4` 重采样、`MAX_CHART_POINTS = 1000` 压缩），可缩放 / 拖拽但只显示 1 个周期。

## 二、实现要点（待方案细化）

1. **数据来源不变**：仿真结果是稳态周期日志（`batteryLog` / `powerLog` / `poolPowerLog` / `burnStateLog`，同长同索引）。两档都只在**展示层按周期平铺（tile）**：`t → ((t mod P) + P) mod P` 取样，不重新仿真、不改求解器与分享码。
2. **周期显示**：生成 `[-0.5P, 1.5P]` 的平铺序列；刻度标签按「相对周期起点」显示（负区间显示为 `-mm:ss` 或以 0 为第一个周期边界加竖向参考线，二选一待定）。缩放下限沿用 `MIN_VISIBLE_SECONDS`，复位范围改为整个 2P 窗口。
3. **时间显示**：窗口长度 `W ∈ {600, 1800, 7200, 43200, 86400, 604800}` 秒，平铺 `ceil(W / P)` 个周期后**先降采样再绘制**——7 days 时 604800s 必须按 `W / MAX_CHART_POINTS` 聚合（功率取段内均值 + 可选 min/max 包络，电量取段内最小值以免掩盖低谷），不能逐秒生成数组（内存与 Chart.js 性能）。
4. **周期封顶的影响**：纯常驻 + 池方案的合成周期按 LCM 封顶 600s，池分支仿真窗口另有 `MAX_POOL_SIMULATION_DURATION`；被封顶的日志不是严格周期，平铺会在拼接处产生跳变。需在方案阶段确认：封顶时是否标注「近似周期」或禁用长时间档。
5. **精确数值开关**：`preciseValues` 模式按仿真 `logSecondsPerPoint` 取原始日志，同样走平铺；`secondsPerPoint` 计算需在两档下统一。
6. **UI**：复用 `ui/Toggle` 或做分段按钮；时间档位用下拉 / 分段选择，仅右档时显示。移动端标题栏宽度已由 `ResizeObserver` 隐藏 `chartDataDesc`，新控件需加入宽度计算。档位是否持久化（localStorage）待定，**不进分享码**。
7. **i18n**：新增「周期显示 / 时间显示」及 6 个时间档文案，8 语言齐全，走 `pnpm run i18n translate add`；changelog 追加到当前小版本小节。
8. **范围外**：蓝图导出 `drawPreciseChart.ts` 的图表是否跟随拨档，默认不跟随（保持单周期），另议。

## 三、验收设想

- 新增 `src/utils/` 纯函数（如 `chartWindow.ts`：平铺 + 降采样）并配 `.test.ts`，断言：2P 窗口首尾 0.5P 与周期中段数据一致；7days 输出点数 ≤ `MAX_CHART_POINTS`；电量低谷不被聚合抹平；`P = 0` / 单点日志不崩。测试须接入 `.github/workflows/ci.yml`。
- `pnpm run i18n translate`、`typecheck`、`lint`、`build` 全过；人工对照游戏「电能报告」10min / 2h 两档曲线形状。

## 四、待决问题

3. 被 600s / 池仿真窗口封顶的近似周期如何提示。
4. 拨档状态是否本地持久化。
